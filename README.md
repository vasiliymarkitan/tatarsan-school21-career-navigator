# Карьерный Навигатор 21

Сайт для участников Школы 21 и тех, кто ищет первую IT-работу в Татарстане. На одной странице живые стажировки и junior-вакансии по Казани, Иннополису, республике и удалёнке по России, плюс новости из четырёх Telegram-каналов.

Вакансии открываются без входа и без выбранной роли. Дайджест в Telegram по желанию. Отдельной регистрации нет. Мессенджер MAX не подключён.

Публичное демо: [http://135.106.187.7:8083](http://135.106.187.7:8083)  
Проверка: [http://135.106.187.7:8083/api/health](http://135.106.187.7:8083/api/health)

## Как это работает

Сервер сам ходит во внешние API. Готовых карточек из репозитория нет. Нет живой ссылки, нет и карточки.

### Вакансии

Спрашиваем два места сразу.

1. Публичный API hh.ru: Татарстан (`area=88`) и junior или стажировки на удалёнке.
2. Yandex Search API v2 (`POST /v2/web/search`) по запросам вроде junior, стажировка, Казань, Татарстан, Иннополис, удалёнка РФ. В запросе стоит `site:hh.ru`.

Роль выбирать не обязательно. Без неё ищем IT junior и стажировки по Казани, Татарстану, Иннополису и удалёнке по России. Роль только сужает выдачу. Telegram для этого не нужен.

Если кэш пустой, сервер ищет сразу. Полчаса до фонового цикла ждать не нужно.

Карточка появляется только при живом `http` или `https` адресе из выдачи. Компанию и зарплату пишем, только когда они уже есть в заголовке или сниппете. Источник такой карточки: `Yandex Search → hh.ru`. Сайт работодателя сами не открываем и не разбираем.

Иногда Yandex всё же отдаёт SuperJob или Habr Career. Тогда на карточке будет `Yandex Search → <хост>`. В список источников этот сайт не попадает.

С VPS hh.ru часто отвечает 403. Тогда карточки держатся на Yandex Search, если у ключа есть доступ к поиску.

Офис в Москве, Минске или Екатеринбурге из ленты убираем. Удалёнка остаётся. Фильтр города: `GET /api/live-vacancies?location=Казань`. На главной есть «Топ-5 за день» из того же кэша (`GET /api/top-day`).

### Новости

Только четыре канала:

- `@kazanit`
- `@it_tatarstan`
- `@innopolis_live`
- `@school21_kazan`

Ищем их в Yandex Search запросами `url:t.me/<канал>/*` и `@канал site:t.me`. Параллельно пробуем HTML-превью `t.me/s/`, если оно не уводит на лендинг Telegram. Других каналов и сайтов нет.

Лента новостей ошибки hh.ru на себя не берёт. Если поиск новостей упал, вакансии от этого не ломаются.

### Дубли

Одинаковые карточки схлопываем по id, по URL, по паре «компания + название» и по очень похожим заголовкам одной компании. То же для новостей: один пост не показываем дважды, если его нашли и через Yandex, и через `t.me/s`.

### Вход и дайджест

Смотреть вакансии и новости можно анонимно. По желанию можно войти через Telegram Login Widget. Сервер кладёт httpOnly JWT. Если `JWT_SECRET` пустой или короче 32 символов, сессию не выдаём. На просмотр ленты это не влияет.

После входа можно сохранить расписание дайджеста (время по Москве), посмотреть превью и отправить подборку сейчас. Планировщик крутится в том же процессе. Почты нет. Если бот не настроен, на экране так и написано. Перед первой доставкой человеку нужно написать боту `/start`, иначе Telegram сообщение не доставит.

### Модель на демо

На демо стоит **YandexGPT Lite** из AI Studio. Можно переключить на GigaChat: `LLM_PROVIDER=gigachat`. Сайт умеет совет по роли, пересказ вакансии парой фраз и план с разбором живой подборки. Карьерный агент берёт карточки из кэша, а не зовёт hh.ru с VPS. Пустой кэш так и пишет, вакансии не выдумывает.

Без `YANDEX_API_KEY` и `YANDEX_FOLDER_ID` парсер hh.ru и превью `t.me/s` всё равно работают. Поиск через Yandex и запросы к модели отвечают 503.

### Когда источников нет

Если упали и hh.ru, и Yandex Search, `GET /api/live-vacancies` отвечает 503. В `/api/health` тот же текст лежит в `fetch_error` и `errors[]`. Пустой ответ без ошибки значит «ничего не нашли», а не спрятанный 403.

### Чего нет и не обещаем

- Мессенджер MAX не подключён.
- Почтового дайджеста нет.
- Карьерные сайты компаний не парсим.
- Отдельной регистрации (имя, почта, пароль) нет.
- `main.py` в корне это старый каркас бота на aiogram. Рабочий путь: FastAPI и `docker compose`.

## Как устроен код

Снаружи nginx слушает **8083** и отдаёт запросы в приложение на **8000**. Приложение: FastAPI в `api_server.py` и обычный JavaScript в `web/`, без отдельного фронтенд-сборщика.

Кэш вакансий, новостей и ошибок живёт в памяти процесса. Воркеров uvicorn один, иначе у каждого будет свой кэш и свой планировщик дайджеста. На диск уезжают только настройки дайджеста.

```
api_server.py          FastAPI, кэш, ручки сайта
auth_utils.py          JWT и проверка входа через Telegram
ai/provider.py         переключатель yandex / gigachat
ai/yandex.py           YandexGPT Lite / AI Studio
ai/giga.py             GigaChat, если его включили
parser/hh_parser.py    публичный API hh.ru
parser/yandex_search.py    Search API v2, карточка только с живым URL
parser/tg_parser.py    превью t.me/s по четырём каналам
parser/dedup.py        дубли вакансий и новостей
parser/geo.py          Татарстан / удалёнка, без офисного шума других городов
digest/                настройки, превью, Bot API, планировщик
web/                   статичная страница
docker-compose.yml     nginx :8083 → app :8000
tests/                 pytest
```

Поиск вакансий и новостей идёт из фона и по первому запросу, если кэш ещё пуст. Проверка того же процесса: `/api/health`.

Yandex Search зовём обычным REST: `POST https://searchapi.api.cloud.yandex.net/v2/web/search`. В ответе `rawData` с XML, не готовые JSON-карточки. Разбираем `<doc>`: адрес, заголовок, сниппет. Отложенный `searchAsync` не используем. Ключ в заголовке `Api-Key`, `folderId` в теле. Запасной путь: IAM `Bearer` и `YANDEX_IAM_TOKEN`. К каталогу нужен биллинг-аккаунт, иначе запросы не пойдут. Если пришёл 401 или 403, пишем ошибку и фейковые карточки не рисуем. Часто помогает роль `search-api.webSearch.user` / `search-api.executor` или scope `yc.search-api.execute`. Если GPT-ключ поиск не умеет, на сервер кладут отдельный `YANDEX_SEARCH_API_KEY` и в git его не коммитят.

Документация поиска: [понятия Search API](https://aistudio.yandex.ru/docs/ru/search-api/concepts/) и [быстрый старт](https://aistudio.yandex.ru/docs/ru/search-api/). Инструмент Web Search у агента AI Studio это другой продукт: модель сама вызывает tool. Мы им не пользуемся.

## Как запустить у себя

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt
cp .env.example .env
# впишите JWT_SECRET от 32 символов. Остальное можно не трогать, если просто смотреть вакансии.

CN21_DISABLE_BACKGROUND=1 pytest -q

uvicorn api_server:app --reload --port 8000
```

Сайт: http://localhost:8000

CI гоняет тот же `pytest` на Python 3.11, файл `.github/workflows/ci.yml`.

## Docker и общее демо

Снаружи порт **8083**. Порты 80 и 443 этот compose не занимает.

```bash
cp .env.example .env
# для входа нужен JWT_SECRET
# для дайджеста ещё TELEGRAM_BOT_TOKEN и BOT_USERNAME
# для модели и поиска на демо: YANDEX_API_KEY, YANDEX_FOLDER_ID, LLM_PROVIDER=yandex
# если у ключа нет yc.search-api.execute, добавьте YANDEX_SEARCH_API_KEY
docker compose up --build -d
```

Открыть: http://localhost:8083  
Проверка: http://localhost:8083/api/health

Общий сервер: `135.106.187.7`, каталог `/opt/tatarsan/school21`, снаружи порт `8083`. SSH и выкладку делает координатор. Агент на чужие машины ничего не копирует.

Демо: http://135.106.187.7:8083

`COOKIE_SECURE=true` имеет смысл только когда перед сайтом появится HTTPS. На голом `:8083` оставьте `false`.

## Переменные

Коротко о главных. Остальные имена лежат в `.env.example`.

| Переменная | Когда нужна | Зачем |
|---|---|---|
| `JWT_SECRET` | вход | от 32 символов, не заглушка из примера |
| `TELEGRAM_BOT_TOKEN` | вход и дайджест | токен у @BotFather |
| `BOT_USERNAME` | виджет входа | username без `@` |
| `LLM_PROVIDER` | нет | `yandex` по умолчанию или `gigachat` |
| `YANDEX_API_KEY` | модель и поиск | API-ключ. Для GPT нужен scope языковых моделей, для поиска ещё `yc.search-api.execute` |
| `YANDEX_FOLDER_ID` | модель и поиск | folder id (`b1g…`), модель `gpt://<folder>/yandexgpt-lite/latest` |
| `YANDEX_SEARCH_API_KEY` | нет | отдельный ключ Search API, если обычный не умеет поиск. Не выдумывать и не коммитить |
| `YANDEX_SEARCH_API_URL` | нет | по умолчанию `https://searchapi.api.cloud.yandex.net` |
| `YANDEX_MODEL` | нет | по умолчанию `yandexgpt-lite` |
| `YANDEX_API_BASE` | нет | `https://ai.api.cloud.yandex.net/v1` |
| `GIGACHAT_CREDENTIALS` | только при `LLM_PROVIDER=gigachat` | ключ Сбера |
| `COOKIE_SECURE` | нет | `true` только за HTTPS |
| `HH_USER_AGENT` | нет | свой UA без личного email |
